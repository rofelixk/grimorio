# Data Model: Collections Foundation

**Feature**: `008-collections-foundation` | **Date**: 2026-09-28

## Collection (new, stored and synced)

`core/models/collection.model.ts`

| Field | Type | Rules |
|---|---|---|
| `id` | `string` (UUID) | Generated by `CollectionService.create`; immutable |
| `name` | `string` | Stored trimmed; 1–40 characters; unique among siblings by `trim().toLocaleLowerCase('pt-BR')` (FR-003, R12) |
| `color` | `CollectionColorId` | One of the 16 palette ids (R11) |
| `parentId` | `string \| null` | `null` for a top-level collection; immutable in this slice (no move) |
| `updatedAt` | `string` (ISO) | Stamped by the service on every create and edit; callers never pass it |

The owner is implicit: one IndexedDB database per profile locally, and `user_id` in the cloud (FR-001).

**Never stored**: counts, card lists, depth and kind (FR-020). They are derived (see "Derived state" below).

**Validation** (`validateCollectionName(name, siblings, selfId?)` in `collection-tree.util.ts`) returns one of:

| Result | When | Copy |
|---|---|---|
| `'empty'` | trimmed length 0 | "Dê um nome à coleção." |
| `'too-long'` | trimmed length > 40 | "Use no máximo 40 caracteres." |
| `'taken'` | a sibling (other than `selfId`) has the same normalized name | "Já existe uma coleção com esse nome aqui." |
| `null` | valid | — |

## Owned card (existing, record unchanged)

`CardEntry` keeps its shape, including `locationId: string` (FR-024). This spec reads `locationId`, `quantity` and `forSale`, and writes only:
- **delete-cards**: the removal of the entries in the subtree, plus their tombstones;
- **create-with-move (FR-029)**: `locationId` changes to the new subcollection's id, with a fresh `updatedAt`.

**Holding-box membership (R1)**: a card is in the holding box when its `locationId` isn't the id of one of the profile's collections. Nothing marks it.

## Tombstone (existing)

`TombstoneRecord { key: '{entity}:{id}', entity, id, deletedAt }`. `TombstoneEntity` becomes `'cards' | 'collections'`, replacing `'locations'`. Collection tombstones are written in the same transaction as the delete (R7).

| Store | Key | Value | Change |
|---|---|---|---|
| `collections` | `id` | `Collection` | **new** |
| `locations` | — | — | **deleted** by the v2 upgrade (R13) |
| `cards` | `id` | `CardEntry` | unchanged |
| `decks`, `meta` | | | unchanged |

Writes from `CollectionService` go through `writeRows` (R2): puts and deletes by key, never a store rewrite.

## Derived state (in `CollectionService`, never stored)

```text
collections        Collection[] (signal)
byId               Map<id, Collection>
childrenOf         Map<parentId | null, Collection[]>   sorted per R12
depth(id)          1 | 2 | 3                             1 + number of ancestors
path(id)           Collection[]                          root → id
subtreeIds(id)     string[]                              id and all descendants
stats              {
                     byId: Map<id, { cards, sale, subs, directEntries }>,
                     holding: { cards, sale }
                   }                                      one pass over cards (R3)
kind(id)           'empty' | 'cards' | 'subcollections'  R4
```

- `cards`/`sale` sum `quantity` over the whole subtree, with `sale` only counting `forSale` entries (FR-007).
- `subs` counts descendants at every level.
- `directEntries` counts entries placed directly in the collection, and decides the `'cards'` kind.

## State transitions

```text
                      create child (parent kind 'cards' → move its direct cards)
      ┌──────────┐  ──────────────────────────────────────────▶  ┌──────────────────┐
      │  empty   │                                                │ subcollections   │
      └──────────┘  ◀──────────────────────────────────────────  └──────────────────┘
   (later: add cards)          delete last child (FR-028)
          │  ▲
          ▼  │ (later card spec: last card leaves)
      ┌──────────┐   create child: moves all direct cards (FR-029)
      │  cards   │  ──────────────────────────────────────────▶  subcollections
      └──────────┘
```

- Level 3: `empty` ↔ `cards` only. Creating a child is rejected.
- **Delete (subtree S, choice)**, as one transaction:
  - `'move'`: delete S's collections and write their tombstones. Cards are untouched and fall into the holding box (R1).
  - `'delete'`: delete S's collections and every card whose `locationId ∈ S`, and write all their tombstones.
  - No cards in S: no choice is asked for; it's the same as `'move'`, with zero cards.
