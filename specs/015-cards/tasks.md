# Tasks: Cards

**Input**: Design documents from `/specs/015-cards/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/services.md, contracts/supabase.md, ui.md, quickstart.md

**Tests**: Requested. plan.md gives every new or changed unit a colocated `.spec.ts`, and quickstart.md "Automated checks" lists the cases each must cover. Each task below writes its unit's spec in the same task.

**Organization**: Tasks are grouped by user story. US2 (see the cards) comes before US1 (add a card), although both are P1: US1's independent test ("the card appears in the collection's list") needs the grid US2 builds, while US2 can be checked with seeded cards. US3 and US4 extend US1's flow; US5 checks the sync carries the changed record.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: Can run in parallel (different files, no dependencies)
- **[Story]**: Which user story this task belongs to (US1–US5)

## Conventions for every task

- Research ids (R1–R20) refer to [research.md](research.md); types and state machines to [data-model.md](data-model.md); signatures to [contracts/services.md](contracts/services.md); SQL and client calls to [contracts/supabase.md](contracts/supabase.md); layout, states, flow, accessibility and copy to [ui.md](ui.md) (§ numbers).
- The visual source is `design_handoff_cards/` (README, `UPDATE-D1b-duplicata-multipla.md`, the `.dc.html` mocks). Exact px, tokens and timings come from there through DESIGN.md.
- Edit existing files with the Edit tool only (mixed CRLF/LF repo).
- New components: standalone, `ChangeDetectionStrategy.OnPush`, imports through the path aliases (`@models`, `@services`, `@utils`, `@testing`, `@shared`, `@db`).
- Every PT-BR string lives in `src/app/core/utils/card-copy.ts` (`CARD`); no component hardcodes text. No `error.message` ever reaches the UI (FR-025).
- No flow starts a sync (FR-023).
- The catalog is swapped in specs through a TestBed provider for `CardCatalogService`, never `vi.mock`.
- Tests and lint run through the `test-runner` agent. Every phase touching `.html`/`.scss`/component `.ts` runs the `design-auditor` agent before its commit and fixes what it reports.
