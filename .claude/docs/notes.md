## 2026-09-16

- New `src/styles/_motion.scss` partial: shared `--ease-standard`/`--duration-fast/base/slow` timing tokens, `@keyframes spin`, and a `.spinner` loading utility. Imported in `styles.scss` alongside `buttons`/`forms`. New components needing transitions/animations should reuse these tokens instead of retyping timing values.
- New tokens in `_tokens.scss`: `--shadow-glow-primary-strong` (ember glow for primary-button hover/focus), `--ring-accent` (teal glow-style focus ring, used in place of a hard `outline` on newer components).
- The CSS grid-rows accordion trick (`display: grid; grid-template-rows: 0fr` → `1fr` on a wrapper, `overflow: hidden` on its inner child) animates a block's height without JS measurement — used in `auth-modal` for the sign-up-only field and the submit spinner. Pair a collapsed wrapper with `[attr.inert]` when it holds a focusable control, so it's skipped from the tab order while hidden.
- New `src/app/shared/color-theme-picker/` + `src/app/core/services/theme.service.ts`: a concept-test feature letting sign-up (and Profile) pick up to 3 MTG colors (W/U/B/R/G) that retint `auth-modal`'s own ring/glow/tab/button *locally*, not app-wide. Pattern worth reusing for any future component-scoped (non-global-token) runtime theming: define short aliases with fallback chains once on the root element (e.g. `--mp: var(--modal-primary, var(--color-primary));`), then reference the short alias everywhere else in that component's stylesheet instead of repeating the full `var(--x, var(--y))` chain per rule — keeps compiled CSS well under the `anyComponentStyle` 8kB error budget in `angular.json`.
- `public/assets/mana/`: all 84 MTG mana/card symbol SVGs fetched from Scryfall's `/symbology` API, plus a `manifest.json` describing each (symbol, english name, colors, hybrid/phyrexian flags). Only the 5 WUBRG icons are wired up so far (the theme picker); the rest are fetched for future mana-cost rendering.
- `auth-modal.scss` uses CSS relative-color syntax `rgb(from var(--x) r g b / pct%)` rather than `color-mix()` for alpha-blended glow effects — meaningfully shorter compiled output for the same effect, same modern-browser baseline as `color-mix()` already in use.
- A negative margin used to "reclaim" padding added for a box-shadow ring/glow doesn't survive being the first/last child of an `overflow: hidden` ancestor whose size is auto (e.g. the grid-rows accordion's `.collapse-inner`): the ancestor sizes itself to the normal-flow box, then clips anything the negative margin pushed past that boundary. Give the ring real, uncompensated padding instead.
- New `src/styles/_modal.scss` partial: mixins for shared `<dialog>`-based modal chrome — `modal-surface`, `modal-scroll-body` (themed scrollbar), `dialog-mobile-fullbleed`, `dialog-reduced-motion`, `theme-ring`/`theme-ambient-glow` (the conic-gradient ring/halo retinting recipe), and `glow-button` (dark-surface + colored border/text `.btn-primary` override, with an optional hover-color swap or a `brightness()` fallback for card-driven colors with no matching hover shade). Imported via `@use 'modal' as m;` — new modals should reuse these instead of re-copying auth-modal's CSS.
- `_motion.scss`'s shared `.spark`/`@keyframes spark-burst` now expose `--spark-peak-opacity`/`--spark-end-scale` custom properties so a caller can tune burst intensity without redeclaring the keyframe.
- `_forms.scss`/`_buttons.scss` gained global `label`, `.error`, and `.close-button`/`.back-button` base rules — don't re-declare these locally in new components.
- `_tokens.scss` gained `--overlay-backdrop` for `<dialog>::backdrop` — use it instead of a raw `rgba(0,0,0,0.75)`.
- Two-typeface system: Grenze (display) + Karla (sans), loaded via Google Fonts `<link>`s in `src/index.html` (`font-display: swap`, not self-hosted). New `_tokens.scss` tokens `--font-display`/`--font-sans`; `body` in `styles.scss` sets `font-family: var(--font-sans)` and all controls keep inheriting it via `font: inherit`. `--font-display` is reserved for card names and page/section titles only — currently applied at exactly one call site (the confirm-dialog card name in `card-add-detail-panel.scss`); nothing else should pick it up by default.
- First use of `linkedSignal` in the codebase (`card-add-detail-panel.ts`'s `faceIndex`, resetting to `0` whenever the `candidate` input changes) — the idiom for "writable local state that resyncs from an input/signal," distinct from `computed` (pure derivation, not writable) and `effect` (side effects, not state derivation).
- First use of `:has()` in the codebase — a custom checkbox visual (real `<input type="checkbox">` kept in the DOM at `opacity:0` for keyboard/AT behavior, sibling `.checkbox-box`/glyph styled via `.checkbox-field:has(:checked)`). Reuse this pattern for future custom checkboxes instead of `appearance: none` hacks. Note: a bare class selector for the checkbox row's `flex-direction: row` can lose to an earlier, more specific combinator selector (e.g. `.right-column label`) despite CSS source order — qualify the override (`.right-column label.checkbox-field`) rather than relying on declaration order.

## 2026-09-17

- New `themed-scrollbar($axis: vertical)` mixin in `_modal.scss`, extracted from `modal-scroll-body`'s inline scrollbar styling — any scroll container (not just modals) should use this for a themed scrollbar instead of repeating the browser-scrollbar-override rules. `modal-scroll-body` now just includes it.
- `card-search-panel.scss`'s rotated-scatter card spread (seeded `sin()`/`cos()` transform, hover un-rotate+lift+scale, multicolor conic ring) is now reused verbatim by `collection-card-grid` (`src/app/shared/collection-card-grid/`) for the Collection Detail grade view — treat it as a shared idiom for card-art grids, not a one-off pattern local to search results.
- New `--core-color` typed custom property (`@property`, syntax `<color>`) + `@keyframes core-color-cycle` in `_motion.scss`: smoothly cycles an element through *all* of the user's chosen identity colors instead of a static 2-color blend (typed custom properties are what makes the browser interpolate between real color values rather than snapping). A caller defines `--identity-primary`/`--identity-accent`/`--identity-tertiary` locally (aliased to its own theme-role host bindings) and applies `animation: core-color-cycle <duration> linear infinite`. Two call sites so far: the collection header's leyline core (`src/app/shared/leyline-field/leyline-field.scss`) and the Collection Detail header glow (`collection-detail.scss`) — reuse this instead of hand-rolling a new cycling keyframe for any future "glow through all my theme colors" effect.
- The theme-role host-binding convention (`--<component>-primary/-accent/-tertiary` set from `theme.service.ts`'s `roles()`, aliased down with a `var(x, var(y))` fallback chain) is now used on two non-modal, page-level components (`collection-header`, `collection-detail`) in addition to the modals it started on (`auth-modal`, `add-card-modal`) — confirmed general-purpose, not modal-specific.
- The shared `.spark`/`@keyframes spark-burst` rule's (`_motion.scss`) per-caller override surface now also includes `--base-angle`/`--spread` (constrain sparks to a directional cone instead of a full circle — center = `--base-angle`, half-width = `--spread`) and `--dur` itself (not just `--spark-peak-opacity`/`--spark-end-scale`): a caller's own component stylesheet can redeclare any of these because Angular's compiled component selectors are more specific than the plain global `.spark` class, so the override wins without touching `_motion.scss`. See `leyline-field.scss`'s sparks for an example overriding all three at once.
